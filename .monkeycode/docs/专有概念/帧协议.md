# 帧协议

tinyjsapp launcher 与 PHP 后端之间的**一行一帧**文本协议，由 `Tiny\Gui\Protocol` 编解码、`Tiny\Gui\Backend` 泵送。存在原因：宿主不执行 PHP；PHP 不直接连命名管道。

## 什么是帧协议？

**关键特征**:
- 分隔符是 `\n`，字段内禁止未转义换行
- 请求是 `CALL`，应答是 `RET`；对话框是 `DLG` 且无 RET
- 窗口控制帧（`TITLE`/`SIZE`/`QUIT`/`MENU*`）必须在对应 RET 之前发出

## 代码位置

| 方面 | 位置 |
|---|---|
| 编解码 | `gui/php/src/Tiny/Gui/Protocol.php` |
| 泵 | `gui/php/src/Tiny/Gui/Backend.php` |
| 请求/应答对象 | `Request.php` / `Response.php` |
| 测试 | `gui/php/test/smoke.php` |
| 上游对齐 | `gui/host/src/launcher-*.cc`、`gui/runtime/tiny.js` |

## 结构

CALL 体常见为 JSON 数组：`["{\"method\":\"ping\",\"params\":{}}", "<origin>"]`。`id` 可含 `win:seq`，`:` 前为 `Request::$callerWin`。

## 不变量

1. **stdout 纯净**：任何非帧字节都会破坏 launcher 解析。
2. **能解析 id 的坏 CALL 必须 RET**：避免对端一直等。
3. **jenc 失败不得写出 `false`**：`JSON_THROW_ON_ERROR` + `Backend::safeRet`。

## 生命周期

```mermaid
stateDiagram-v2
    [*] --> READY: Backend::run 写 READY
    READY --> Pump: fread stdin
    Pump --> Decode: Protocol::decode
    Decode --> Ignore: type ignore
    Decode --> BadCall: type bad_call
    Decode --> Notify: type notification
    Decode --> Call: type call
    BadCall --> Pump: RET status 1
    Notify --> Pump: EVAL 或编码失败则 null
    Call --> DLG: dialog.*
    Call --> RET: 其他 method
    DLG --> Pump
    RET --> Pump
```
