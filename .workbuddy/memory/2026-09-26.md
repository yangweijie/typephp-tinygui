## 套件按"分发地"重验（同 session 收尾）

- 规矩：**kit 资产只有在它被分发到的位置（技能目录）跑起来才算验过**。in-tree 全绿 → 技能目录跑出
  `TIER1_RC=1`、`STDERR_RC=1`。修好三个真 bug + 一条假通过断言：
  1. `$WORK/app.sock` 在技能目录下恰好 108B = `sun_path` 上限 → `typephp_default_work`（standalone 用
     短临时 scratch）+ `typephp_socket_path`（超长则挪 `/tmp/tpkit.*`，`EXIT` trap 清理）。
  2. `all.sh` 编 `host_probe` 前没有 `mkdir -p "$WORK"`。
  3. "求默认值"的函数无视显式 `WORK=` → 一次 standalone 留下 9 个空临时目录；现 `WORK` 立即短路。
  4. launch 档断言写死 `$WORK/app.sock`，而端点名由入口自取（超长回退 `/tmp/tinyjs-typephp-<pid>.sock`）
     → 分发侧**无条件通过**。改为从 shim 日志读回 `transport=unix-socket pipe=…`。
- 结果：in-tree 与 standalone 都 **51 PASS / 0 FAIL / ALL TIERS OK**；临时目录 0 / 恰好 1。
- 同步纪律：kit 的 standalone 运行不写自己的目录，所以"同步进技能后 `diff -rq` 两边"永远干净。

## GUI 融合：build/publish 真机验证 + 修复（本次续做）

- 用户要求对 `tgui build` / `tgui publish` 跑一轮真机验证（本机工具链齐全：MSVC 2022 BuildTools、MinGW g++、tpc、系统 PHP、WebView2 SDK）。
- 发现并修复 `gui/bin/tgui` 的 `build` 子命令三个真 bug：
  1. shim 与 PHP 后端都拷到 `dist/app.exe` 互相覆盖 → 入口 shim 丢失。改为 shim→`<App>.exe`（入口），PHP 后端→`php.exe`（独立名）。二者**不能同名**，否则 conf 里 `app=` 指回 shim 形成死循环。
  2. 漏拷 MinGW 运行时 `libgcc_s_seh-1.dll` + `libstdc++-6.dll`（launcher 与 shim 都依赖）→ dist 加载失败。现从 `build/runtime/*.dll`（MinGW）+ `build/*.dll`（PHP 运行时）一并拷入。
  3. `set -u` 下 `FE_DIR` 在 build 分支未定义 → "unbound variable" 中止；`name` 含空格生成的 exe 带空格，已 `NAME="${NAME// /-}"` 净化。
- 真机验证（模拟双击 `dist/TypePHP-Demo.exe`=shim 的 launch_mode）：
  - shim 自建命名管道端点、拉起 `php.exe`(PHP AOT) 与 `launcher.exe`(STOCK 宿主)，完整协议流：client.hello / menu.set(TAB 帧) / ping→pong / sysinfo(PHP 8.5.11 + aot-compiler AOT native) / api.fib(40)=102334155 / api.sha256 / api.sum(1..100)=5050 / listDir / theme.get / system.locale / win.getState，结尾 `backend stderr: "WINDOW-E2E OK ping=pong in ~400ms"`。
  - shim 在 launcher 退出后干净收尾（launcher closed → closing → done）。
- `tgui publish` 产出 `dist.tar.gz`（~7.6MB）；本机无 `zip` 自动回退 `tar -czf`（脚本设计如此）。
- 提交：修复 + `.gitignore` 加 `dist.zip`/`dist.tar.gz` + `docs/GUI_FUSION_DESIGN.md` 同步（集成图/打包方向/DLL 计数/验证结论）。`gui/` 模块本身已于 f8202d0 提交。
- 教训：原生 Windows 二进制（shim/launcher）读 `TYPEPHP_SHELL_LOG` 时**不接受 `/d/git/...` Unix 路径**，必须给 `D:/git/...` 原生 Windows 路径，否则 fopen 失败、日志为空（stdout 仍可验证）。
- 清理：杀 dist 进程在 Git Bash 下 `taskkill //T //PID` 不灵，改用 PowerShell `Stop-Process -Force` 按路径 `*typephp-gui\demo\dist*` 精确清理。
